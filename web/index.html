Read this first

The ESP32 publishes one frame per second to the public MQTT broker; this page only displays what arrives. Separately, the board stores GPS fixes in Cloudflare, and HIST reads those back. Pills are green when healthy, yellow when waiting, red when something is wrong. There is no login: anyone with the link sees the same screen.

Status pills

BROKER
BROKER OK = this page's WebSocket to the broker is open. BROKER ... = still connecting, or reconnecting after a drop.
DEVICE
DEVICE LIVE = a frame arrived in the last 6 seconds. NO SIGNAL = the link is fine but the board went quiet. DEVICE OFFLINE = the board announced it is going away (shutdown, Wi-Fi loss, power cut).
ACS
ACS OK = the firmware found the current sensor: its zero sits near half supply (~2.5 V) and the amps are plausible. ACS CHECK = floating pin, wrong wiring, or impossible readings, so current is not trustworthy.
MPU6050
MPU OK = the tilt sensor answered and its numbers passed the range check. MPU FAIL = missing or unreadable, so tilt and the danger lights are unknown.
GPS
GPS FIX = the receiver has a valid position. GPS WAIT = serial data is arriving but there is no fix yet (indoors, or a cold start: can take minutes). GPS NO DATA = nothing on the serial line (wiring or baud rate).

Map corner

SPEED (map)
Ground speed of the last fix, km/h. Shows 0.0 while the page agrees the vehicle is parked (receivers report 1–2 km/h of noise) and NO FIX when there is no position.
TRIP
Length of the trail this page has drawn since it was opened. It is not stored anywhere and returns to 0 on reload.
HEADING (map)
Direction of travel in degrees: 0 = north, 90 = east, 180 = south. Taken from GPS when moving with a good HDOP, otherwise from the MPU6050, so it can be a couple of degrees off.
Position
Latitude and longitude of the last valid fix, plus the nearest street address (OpenStreetMap). locating address... means it is still resolving; the numbers above it are already current.
MEASURE A→B
Operator tool: tap two points on the map to get the distance between them. Nothing is uploaded.

LIVE tab

Speed
Same value as the map corner: last GPS ground speed in km/h.
Altitude
GPS altitude in metres. Noisy by ±5–10 m and not barometric, so treat small changes as noise.
Sats
Satellites used in the current fix. 6 or more works, 9–12 is good, under 4 means no fix.
HDOP
Horizontal dilution of precision: a geometry score, lower is better. Under 2 is excellent, 2–5 is good, over 8 is poor. Above 8 the firmware stops publishing a position even though it still has a fix, which is why you can see satellites but NO FIX.
Fix
VALID = the receiver says the position is usable. NO FIX = it does not, so coordinates are sent as empty.
Heading
Course in degrees, from GPS or MPU6050 (see map corner).
Tilt
How far the vehicle is leaning, from the MPU6050, in degrees. This is the number the danger lights use.
Amps
Current in amperes from the ACS712. ERR means the sensor is not present or not calibrated, so the number would be fiction.
Odometer
Distance in metres the firmware has counted since it booted, minus any reset you did in this browser. It drops to 0 when the board reboots; the ↻ button (unlocked) zeroes it just for this browser.
Trail
Distance in km of the breadcrumb line on the map. Browser-side only: reload clears it.
Address
Nearest street to the last fix, as resolved above. It lags the coordinates slightly because the lookup is rate-limited.
Max Speed
Fastest speed this page has seen since it opened, not the device's all-time record.
Seq
The device's frame counter. It rises by about 1 per second; a jump means frames were lost in transit.
Gaps
How many frames went missing between Seq jumps since this page opened. A few after a Wi-Fi hiccup is normal (live MQTT is best-effort); stored history is unaffected because the board uploads it separately from flash.
Age
Seconds since the last frame reached this browser. About 1 s is normal; over 6 s and DEVICE turns to NO SIGNAL.
Device Time
The board's UTC clock (hh:mm:ss), set from GPS. no clock means it has not seen a GPS time yet; stored fixes are stamped with the same clock.
GPS Lat / GPS Lng / GPS Alt / GPS Spd
The same position and speed again, raw, for copying or checking against another device. They follow Fix: NO FIX when there is no position.
Uptime
Seconds since the board booted. A number that starts over means it rebooted.
RSSI
Wi-Fi signal at the board, in dBm. −50 is excellent, −70 is fine, −85 is weak, below −90 causes dropouts.
Heap
Free RAM right now, in KB. High hundreds is healthy on this build; a value that keeps shrinking over hours means a leak.
GPS Sats
Satellite count again, straight from the receiver.

Danger lights

BLUE safe
Tilt is below the warning angle. Normal driving.
WHITE warn
Tilt passed the warning angle (30° by default): the vehicle is leaning more than it should.
RED danger
Tilt passed the danger angle (50° by default): likely a crash or rollover.
all off
No MPU6050 data, so the page cannot judge. This is accident indication only, not a lock and not a security feature.

WIFI tab

Uptime (WIFI)
Same as LIVE: seconds since boot.
WiFi RSSI
Signal strength at the board in dBm (−50 great → −90 unusable).
Free Heap
Free RAM right now, in KB. Healthy readings sit well above the lowest point this build has ever needed.
Min Heap
The lowest free RAM since boot. This is the leak detector: Free Heap bounces, Min Heap only falls.
Boots
How many times the board has started. Climbing on its own means crashes or brownouts.
Last Update
Local time this browser last received a frame.
SSID / BSSID
Wi-Fi network name, and the MAC of the access point it is attached to (useful when a venue has several identical hotspots).
Channel
Wi-Fi channel in use. 1/6/11 are the non-overlapping 2.4 GHz ones.
Status (WIFI)
Association state reported by the board.
IP Address
The board's address on the local network.
MAC
The board's own Wi-Fi MAC. Use it in a DHCP reservation so the address never changes.

MPU tab

Temp
Chip temperature in °C, a few degrees above ambient. It is not engine or air temperature.
Roll / Pitch
Lean left-right (roll) and nose up-down (pitch) in degrees, from gravity.
Yaw
Turn around the vertical axis, in degrees, integrated from the gyro. It drifts over time because there is no magnetometer, so trust GPS HEADING when moving.
Max Tilt
The largest tilt seen since boot. It survives nothing: a reboot clears it.
Accel X / Accel Y / Accel Z
Acceleration in g (1 g = gravity). Sitting still, one axis reads about ±1 and the others near 0. Cornering and bumps show up here.
Tilt (MPU)
Current combined tilt: the angle that drives the danger lights.
Warn at / Danger at
The thresholds in force, in degrees. The board uses the same values to pick the LED level.
tilt history
The last 120 samples (about two minutes at one frame per second) drawn as a line, so a spike is visible even after it passed.

ACS tab

Module V
Sensor output voltage with the divider undone. At 0 A it should sit near 2.5 V; far from that means the sensor is unplugged or the pin is floating.
Zero
The voltage treated as 0 A. Calibrated once, because every module is slightly different.
Current
(Module V − Zero) ÷ sensitivity, in amperes. Signed: negative means current flowing the other way. ERR when the sensor is not present.
Peak
Highest current the firmware has held recently (peak hold).
Status (ACS)
Plain verdict: OK, OK — idle (0 A), OUT OF RANGE (wrong model or divider), or NO SIGNAL (nothing connected).
Model
Picks the sensitivity preset: 5 A = 185 mV/A, 20 A = 100 mV/A, 30 A = 66 mV/A. Match the board you actually wired.
Sensitivity (V/A)
Volts of output change per ampere. Only edit it for a module that is not one of the three presets.
Divider ratio
How much your voltage divider scales the sensor output before the ADC. Default 0.6875 matches this build; change it only if you wired a different divider, or every amp reading shifts.
Zero (V)
Manual zero. Leave it empty (auto) to follow the firmware.
Zero now / Device zero / Defaults
Zero now adopts the current reading as 0 A (do it with the motor off). Device zero goes back to the firmware's value. Defaults restores 5 A / 0.185 / 0.6875 / auto.

HIST tab

HIST is not live data: it asks the Cloudflare API what the board stored and drew on the map, in UTC. 1 h / 6 h / 24 h is the window, ending now.

Points
How many stored fixes are drawn for the window. The board records one per second while moving and one per 10 s while parked, and only when it has a fix. Wide windows are sampled by the server so they still cover the whole window; Status then says 1 of N points, T total, where T is what is really stored.
Distance
Sum of the straight lines between the drawn points, in km. Sampling cuts corners, so a sampled window can read slightly low.
Max gap
The longest wait between two stored fixes in that window, measured on the raw data so sampling never fakes a gap. About 1 s while moving and about 10 s while parked are normal. Bigger means data was missing: no GPS, no internet, a reboot, or the board was off.
Window
The exact UTC start and end the API answered with.
Status (HIST)
What happened: loaded, sampled, truncated at the row cap, empty, or an error such as the API being unreachable.

What is normal

A healthy parked board
Age 1–2 s, Speed 0.0, Gaps barely moving, HDOP under 5, Sats 7+, Min Heap flat, Max gap in HIST around 10 s.
A healthy moving board
Seq rising, Gaps flat, HDOP under 5, Max gap in HIST around 1 s, heading following the turns.
Worth investigating
Age over 6 s repeatedly, Gaps climbing, Min Heap falling every hour, Boots climbing, HDOP pinned above 8, or a HIST max gap far above 10 s with no parked period to explain it.
