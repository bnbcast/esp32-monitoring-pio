History API (Cloudflare Pages Function)

Base URL: https://race-tracker-history.pages.dev

Public read; write requires the ingest secret. All responses are JSON with CORS access-control-allow-origin: *.

Endpoints

MethodPathAuthDescription
GET/health—Liveness
GET/history—Query stored fixes + laps
POST/ingestX-Ingest-KeyDevice batch upload
OPTIONS*—CORS preflight, 204
anyknown path, wrong method—404 { ok:false, error:"not-found" }

Arbitrary unmatched paths never reach the function on the Pages deployment: Pages falls back to public/index.html and returns the landing page with 200. The router's JSON 404 applies to a known path called with the wrong method (for example POST /health).

POST /ingest

The device batches queued fixes (40 frames / 8 KB, every 30 s).


POST /ingest
Content-Type: application/json
X-Ingest-Key: <secret>


{
  "device": "esp32-01",
  "frames": [
    {
      "seq": 1234, "ts": 1700000001, "up": 3600, "boot": 7,
      "fix": true, "lat": -6.200001, "lng": 106.800001, "alt": 120.4,
      "kmh": 45.2, "cog": 90.5, "hdop": 0.8, "sats": 8,
      "dist_m": 1520.4, "roll": 4.1, "pitch": -2.1,
      "lap_n": 1, "lap_last_ms": 45230, "lap_best_ms": 44210, "lap_gen": 3
    }
  ]
}

Frames may also be wrapped as {"gps":{ "fix","lat","lng",... }} — the worker accepts both the flat device form and the nested live-MQTT form.

Frame Rejection Reasons

shape, clock, stale-boot, stale-seq, range, speed, hdop, teleport, and duplicate (skipped, not counted as an error).

Rejected frames are reported in rejected[] as { "seq": n, "reason": "..." }. Because the device deletes a batch on any 2xx, one permanently bad frame cannot jam the ring buffer.

Response (200)


{
  "ok": true,
  "received": 40,
  "stored": 38,
  "laps": 1,
  "duplicates": 1,
  "rejected": [{ "seq": 1235, "reason": "teleport" }],
  "retention": "skipped"
}
FieldDescription
receivedFrames in the request
storedRows written to D1
lapsLap rows written; -1 = laps table missing (migration not applied)
duplicatesFrames skipped by (boot, seq)
rejected{seq, reason} list

Storage Policy (D1)

RuleDetail
Only valid fixesfix:false frames are accepted but not stored
Moving (≥3 km/h)Every frame (1 Hz)
Parked1 frame / 10 s
Speed gate> 150 km/h rejected
HDOP gate> 8 rejected
Clock gate−7 days … +1 hour
Teleport gatedistance > 1.5 × max speed × Δt + 20 m
Retention365 days, purged at most once a day from ingest

CORS


access-control-allow-origin: *
access-control-allow-methods: GET, POST, OPTIONS
access-control-allow-headers: content-type, x-ingest-key

Device Behavior

  1. LittleFS ring buffer keeps fixes with a valid GPS position and clock.
  2. Every 30 s (or 40 frames) the device sends a batch.
  3. Any 2xx ack deletes the batch locally, even if some frames were rejected.
  4. Network/TLS errors leave the buffer intact for the next cycle.

Examples


# Last hour
curl "https://race-tracker-history.pages.dev/history?from=$(date -d '1 hour ago' +%s)&limit=200"

# Ingest
curl -X POST https://race-tracker-history.pages.dev/ingest \
  -H "Content-Type: application/json" \
  -H "X-Ingest-Key: $INGEST_KEY" \
  -d '{"device":"esp32-01","frames":[{"seq":1,"up":10,"ts":1700000001,"fix":true,"lat":-6.2,"lng":106.8,"kmh":45,"hdop":0.8}]}'
